# 3.1 Introduction and Transport-Layer Services

## Transport Layer Role

- Provides **logical communication** between application processes on different hosts
- Implemented in end systems only — routers see datagrams, not transport segments
- Sending side: breaks app messages into **segments**, passes to network layer
- Receiving side: reassembles segments into messages, passes to application layer

## Transport vs. Network Layer

| Layer | Scope | Analogy |
|-------|-------|---------|
| Network (IP) | host-to-host delivery | postal service (house to house) |
| Transport (TCP/UDP) | process-to-process delivery | household mail distributor (Ann/Bill) |

- Transport services are **constrained** by network layer service model
- BUT transport can provide services the network layer does not (e.g., reliability over unreliable IP)

## Internet Transport Protocols

### IP (Network Layer)
- Best-effort delivery — unreliable service
- No guarantees: delivery, ordering, integrity
- Every host has at least one IP address

### UDP (User Datagram Protocol) — RFC 768
- Extends IP host-to-host to process-to-process (multiplexing/demultiplexing)
- Light error checking (checksum)
- No connection establishment, no reliability, no flow/congestion control
- Unreliable, connectionless

### TCP (Transmission Control Protocol) — RFC 793, 1122, 2018, 5681, 7323
- Multiplexing/demultiplexing
- Reliable data transfer
- Flow control
- Congestion control
- Connection-oriented (three-way handshake)
- Does NOT guarantee delay or bandwidth

## Key Services Transport Can Provide Even Over Unreliable Network

- **Reliable data transfer**: via ACKs, retransmissions, sequence numbers, timers
- **Encryption (TLS)**: implemented above TCP at application layer, not in transport itself

## What Transport Cannot Provide

- Delay guarantees
- Bandwidth guarantees
- (These are constrained by the underlying IP best-effort model)
