# 3.2 Multiplexing and Demultiplexing

## Definitions

- **Multiplexing**: at sender — gather data from multiple sockets, encapsulate with transport header, pass to network layer
- **Demultiplexing**: at receiver — deliver data from received segments to the correct socket/process
- Required for all computer networks whenever a single lower-layer protocol serves multiple upper-layer protocols

## How It Works

- Each socket assigned a **port number** (16-bit: 0–65535)
- Well-known ports: 0–1023 (reserved, RFC 1700, updated at iana.org RFC 3232)
  - HTTP: 80, FTP: 21, DNS: 53, SMTP: 25
- Transport header includes **source port** and **destination port** fields (each 16 bits)
- Receiver examines destination port → directs to correct socket

```
 0                   16                  31
 +--------------------+--------------------+
 |    Source Port     |  Destination Port  |
 +--------------------+--------------------+
 |              ...other fields...         |
```

## Connectionless Demultiplexing (UDP)

- UDP socket identified by **2-tuple**: (destination IP, destination port)
- Segments from different sources but same destination IP + port → same socket
- Source port used as "return address" by receiver

**Example**: Host A (port 19157) → Host B (port 46428)
- Transport creates segment: src=19157, dst=46428
- B receives, looks at dst port 46428, delivers to that socket

```python
clientSocket = socket(AF_INET, SOCK_DGRAM)  # transport auto-assigns ephemeral port
clientSocket.bind(('', 19157))              # or explicit bind
```

## Connection-Oriented Demultiplexing (TCP)

- TCP socket identified by **4-tuple**: (src IP, src port, dst IP, dst port)
- Two segments with same dst port but different src IP or src port → **different sockets**
- Server has a **welcoming socket** on a known port; accepts connections → creates new connection socket per client

**4-tuple match on incoming segment**:
1. Source port
2. Source IP address
3. Destination port
4. Destination IP address

```python
# Server side
serverSocket = socket(AF_INET, SOCK_STREAM)
serverSocket.bind(('', 12000))   # welcoming socket
serverSocket.listen(1)
connectionSocket, addr = serverSocket.accept()  # new socket per client
```

**Example (Figure 3.5)**: Two clients (A, C) connecting to Web server B on port 80:
- Host C: connections use src ports 26145 and 7532 → server creates 2 different sockets
- Host A: may also use src port 26145 — still distinct because src IP differs

## Web Server Threading

- High-performance servers: one process, new **thread** per connection (each thread has own connection socket)
- Not always one-to-one between connections and OS processes
