# 8.2 Principles of Cryptography

## Terminology

- **Plaintext / cleartext** — original message `m`
- **Ciphertext** — encrypted message `KA(m)`
- **Encryption algorithm** — takes key `KA` and plaintext `m`, produces ciphertext
- **Decryption algorithm** — takes key `KB` and ciphertext, recovers `m`
- Encryption algorithms are public; security relies entirely on the key

## 8.2.1 Symmetric Key Cryptography

### Historical Ciphers (weak, for context)

| Cipher | Mechanism | Weakness |
|---|---|---|
| Caesar cipher | Shift each letter by `k` positions | Only 25 possible keys |
| Monoalphabetic | Any letter substitution (unique mapping) | Statistical analysis breaks it; 26! keys but frequency analysis works |
| Polyalphabetic | Multiple Caesar ciphers in repeating pattern | Harder but still breakable |

### Attack Types

- **Ciphertext-only attack** — intruder has only intercepted ciphertext; uses statistical analysis
- **Known-plaintext attack** — intruder knows some (plaintext, ciphertext) pairs
- **Chosen-plaintext attack** — intruder can choose plaintext and obtain ciphertext

### Block Ciphers

- Message processed in blocks of `k` bits
- One-to-one mapping: k-bit cleartext block → k-bit ciphertext block
- For `k=64`: `2^64!` possible mappings — astronomically large

**In practice** — block ciphers simulate random permutations via rounds:
1. Split 64-bit block into 8 × 8-bit chunks
2. Each chunk processed by an 8-bit → 8-bit lookup table
3. Reassemble 64 bits, scramble (permute) positions
4. Repeat `n` rounds — each input bit affects most/all output bits after multiple rounds

**Key algorithms**:

| Cipher | Block Size | Key Size | Notes |
|---|---|---|---|
| DES | 64 bits | 56 bits | Crackable; NIST estimates 1-sec DES crack machine needs 149 trillion years for AES-128 |
| 3DES | 64 bits | 168 bits | Triple-apply DES |
| AES | 128 bits | 128/192/256 bits | Current standard; used in TLS, IPsec, WPA2 |

### Cipher Block Chaining (CBC)

**Problem with naive block encryption**: identical plaintext blocks → identical ciphertext blocks (reveals patterns).

**CBC solution**:

```
c(0) = IV  (Initialization Vector, random k-bit string sent in cleartext)
c(i) = K_S( m(i) XOR c(i-1) )
```

- Receiver recovers: `m(i) = K_S^{-1}(c(i)) XOR c(i-1)`
- Identical plaintext blocks produce different ciphertext (because XOR with different previous ciphertext)
- Only overhead: 1 IV block (negligible for long messages)
- **Protocol implication**: must distribute IV from sender to receiver

**CBC example** (3-bit cipher, plaintext `010 010 010`, IV `001`):
```
c(1) = K_S(010 XOR 001) = K_S(011) = 100
c(2) = K_S(010 XOR 100) = K_S(110) = 000
c(3) = K_S(010 XOR 000) = K_S(010) = 101
```

## 8.2.2 Public Key Encryption

**Introduced by Diffie & Hellman (1976)** — enables secure communication without pre-shared secret.

### Key Model

- Bob has: public key `K_B+` (known to everyone) and private key `K_B-` (known only to Bob)
- Alice encrypts: `c = K_B+(m)`
- Bob decrypts: `m = K_B-(K_B+(m))`
- Property: `K_B-(K_B+(m)) = K_B+(K_B-(m)) = m`

### RSA Algorithm

Named after Rivest, Shamir, Adleman.

**Key generation**:
1. Choose two large primes `p` and `q` (product ~1024 bits recommended)
2. Compute `n = pq`, `z = (p-1)(q-1)`
3. Choose `e < n` such that `gcd(e, z) = 1` (e and z are relatively prime)
4. Find `d` such that `ed mod z = 1`
5. Public key: `(n, e)` — Private key: `(n, d)`

**Encryption** (Alice → Bob):
```
c = m^e mod n
```

**Decryption** (Bob):
```
m = c^d mod n
```

**Why it works**:
```
c^d mod n = (m^e)^d mod n = m^(ed) mod n
```
Since `ed mod z = 1`:
```
m^(ed) mod n = m^(ed mod z) mod n = m^1 mod n = m
```
(By number theory: if `p`, `q` prime, `n=pq`, `z=(p-1)(q-1)`, then `x^y mod n = x^(y mod z) mod n`)

**Security basis**: No known efficient algorithm for factoring large `n` into `p` and `q`. Quantum computing threatens this in the future.

**Example** (`p=5, q=7`, so `n=35, z=24, e=5, d=29`):

| Letter | m | m^e | c = m^e mod 35 |
|---|---|---|---|
| l | 12 | 248832 | 17 |
| o | 15 | 759375 | 15 |
| v | 22 | 5153632 | 22 |
| e | 5 | 3125 | 10 |

### Session Keys (Hybrid Encryption)

RSA is computationally expensive for large data. In practice:

1. Alice chooses symmetric **session key** `K_S`
2. Alice encrypts data with `K_S` (fast symmetric cipher)
3. Alice encrypts `K_S` with Bob's public key: `c = K_S^e mod n`
4. Alice sends encrypted data + encrypted session key to Bob
5. Bob decrypts `K_S` using his private key, then decrypts data

**Used by**: PGP, TLS, IPsec

### Diffie-Hellman

- Different from RSA: cannot encrypt arbitrary messages
- Can establish a shared symmetric session key
- Used in IKE (IPsec key management)
