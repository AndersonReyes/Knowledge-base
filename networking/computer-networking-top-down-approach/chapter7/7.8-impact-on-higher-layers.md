# 7.8 Wireless and Mobility: Impact on Higher-Layer Protocols

## TCP Over Wireless Links

### The Problem
- TCP retransmits on **any** segment loss (congestion, handover delay, or bit error)
- TCP interprets loss as **congestion signal** → decreases congestion window (cwnd)
- In wireless networks, loss is often due to **bit errors** or **handover**, not congestion
- Router buffers may be empty; no congestion; yet TCP still backs off → unnecessary throughput reduction
- Wireless bit error rates are orders of magnitude higher than wired

### Three Approaches to Fix TCP Over Wireless

#### 1. Local Recovery
- Handle bit errors at the wireless link, transparent to TCP
- TCP sender never sees the loss
- Examples:
  - **802.11 ARQ** (link-layer retransmission within the wireless hop)
  - **ARQ + FEC combined** approaches (used in 4G/5G RLC sublayer)
- Benefit: no TCP changes needed
- Limitation: can't recover from handover loss easily

#### 2. TCP Sender Awareness of Wireless Links
- TCP sender and receiver detect whether loss came from wireless corruption vs. wired congestion
- Apply congestion control **only for wired-side losses**
- Research: [Liu 2003] — techniques to distinguish loss sources; [Huang 2013] — LTE-friendly transport mechanisms
- More complex to implement; requires cross-layer signaling

#### 3. Split-Connection Approach
- Break end-to-end TCP connection into two separate transport connections:
  - **Wireless segment:** Mobile host ↔ Wireless access point (may use standard TCP, UDP-based protocol, or selective-repeat protocol)
  - **Wired segment:** Access point ↔ Remote correspondent (standard TCP)
- AP performs protocol translation between the two halves
- Wireless segment can use error recovery optimized for wireless (e.g., high retransmit aggressiveness, no congestion window reduction on bit-error losses)
- **Measurements [Wei 2006]:** split TCP connections widely used in cellular data networks with significant performance improvement

## Application Layer Impact

### Bandwidth Scarcity
- Wireless spectrum is a **shared scarce resource**, especially cellular
- Web servers serving 4G clients should deliver lighter content than for wired connections (fewer images, lower resolution)
- Applications must treat bandwidth as expensive on wireless

### Location-Aware Applications
- Wireless + mobility enables **location-aware** and **context-aware** applications
- Examples: navigation, location-based services, proximity triggers, mobile payments
- Rich set of new application categories not possible with wired-only networks

## Summary of Key Differences: Wired vs. Wireless

| Dimension | Wired | Wireless |
|---|---|---|
| BER | Very low (~10⁻¹²) | Higher (multipath, interference) |
| Loss cause | Congestion (primary) | Congestion + bit errors + handover |
| TCP congestion control | Appropriate | May fire unnecessarily on wireless loss |
| Bandwidth | Abundant (fiber) | Scarce shared spectrum |
| Mobility | Rare/static | Core design concern |
| Application design | Rich media assumed | Must adapt to link quality |
