# 7.3 WiFi: 802.11 Wireless LANs

## 802.11 Standards Summary (Table 7.1)

| Standard | Year | Max Data Rate | Range | Frequency |
|---|---|---|---|---|
| 802.11b | 1999 | 11 Mbps | 30 m | 2.4 GHz |
| 802.11g | 2003 | 54 Mbps | 30 m | 2.4 GHz |
| 802.11n (WiFi 4) | 2009 | 600 Mbps | 70 m | 2.4, 5 GHz |
| 802.11ac (WiFi 5) | 2013 | 3.47 Gbps | 70 m | 5 GHz |
| 802.11ax (WiFi 6) | 2020 | 14 Gbps | 70 m | 2.4, 5 GHz |
| 802.11af | 2014 | 35–560 Mbps | 1 km | Unused TV bands (54–790 MHz) |
| 802.11ah | 2017 | 347 Mbps | 1 km | 900 MHz |

- b/g/n/ac/ax are **backward compatible**
- n/ac/ax use **MIMO** (multiple input multiple output) antennas
- ac/ax support **beamforming** — directs signal toward receiver to reduce interference and extend range
- 2.4 GHz: unlicensed, more interference from appliances; 5 GHz: shorter range, more multipath
- All share same frame format and CSMA/CA MAC protocol; 802.11ax also supports centralized scheduling

## 7.3.1 Architecture

### Basic Service Set (BSS)
- Fundamental building block: one or more wireless stations + one **Access Point (AP)**
- AP connects BSS to larger network (switch/router → Internet)
- Each station and AP has a 6-byte IEEE MAC address (stored in firmware)

### Ad Hoc Mode
- Stations form network without central AP or infrastructure
- Self-organizing; used when no pre-existing infrastructure is available

### Channels and Association

**2.4 GHz band (802.11b/g/n/ax):**
- 2.4 GHz to 2.4835 GHz = 85 MHz band
- Defines 11 partially overlapping channels
- Non-overlapping if separated by ≥ 4 channels
- **Only non-overlapping set of 3 channels: {1, 6, 11}**
- Deploying 3 APs on channels 1, 6, 11 at same location → 3× aggregate throughput

**SSID** — Service Set Identifier; 1–2 word name assigned by admin to AP

### AP Discovery

**Passive scanning:**
1. APs periodically send **beacon frames** (contain SSID + MAC address)
2. Device scans all 11 channels for beacon frames
3. Device selects AP (typically highest signal strength)
4. Sends association request frame → AP responds with association response

**Active scanning:**
1. Device broadcasts **probe request frame** (received by all APs in range)
2. APs respond with probe response frames
3. Device selects AP, sends association request → AP sends association response

After association: device sends DHCP discovery to get IP address in AP's subnet.

**Authentication options:**
- MAC address filtering
- Username/password (cafés)
- AP communicates with auth server via **RADIUS** [RFC 2865] or **DIAMETER** [RFC 6733]

## 7.3.2 The 802.11 MAC Protocol (CSMA/CA)

### Why Not CSMA/CD?
- Collision detection requires simultaneous send + receive — received signal too weak vs. transmitted signal → cost prohibitive
- Hidden terminal problem + fading mean collisions would still be undetectable even if hardware supported it

### Link-Layer ACKs
- High BER → 802.11 uses link-layer ACK/retransmission (ARQ)
- Destination waits **SIFS** (Short Inter-Frame Spacing) after receiving a good frame, then sends ACK
- Sender retransmits if no ACK received within timeout
- Frame discarded after fixed retransmission count

### CSMA/CA Protocol Steps
1. **Channel idle?** → wait **DIFS** (Distributed Inter-Frame Space), then transmit
2. **Channel busy?** → choose random backoff (binary exponential backoff), count down only while channel idle; freeze counter when channel busy
3. When counter hits 0, transmit entire frame, wait for ACK
4. **ACK received?** → success; next frame starts at step 2
   **No ACK?** → re-enter backoff with larger interval

**Key difference from Ethernet CSMA/CD:** 802.11 stations always count down even when channel goes idle (to avoid simultaneous transmission after a busy period).

### Dealing with Hidden Terminals: RTS/CTS

```mermaid
sequenceDiagram
    participant H1
    participant AP
    participant H2
    H1->>AP: RTS (duration field = time for DATA + ACK)
    AP->>H1: CTS (broadcast; heard by H2)
    AP->>H2: CTS (instructs H2 not to transmit)
    H1->>AP: DATA
    AP->>H1: ACK
```

- **RTS (Request to Send)** — short frame from sender to AP; reserves channel
- **CTS (Clear to Send)** — broadcast from AP; heard by all stations including hidden ones → they defer
- **Benefits:** hidden terminal mitigated; collisions only on short RTS/CTS frames, not long DATA frames
- **Cost:** overhead (delay + bandwidth); not always used
- **RTS threshold:** per-station setting; RTS/CTS only used for frames > threshold; default threshold often > max frame size (so RTS/CTS skipped by default)

### Point-to-Point Use
- Two nodes with directional antennas can run 802.11 as a point-to-point link over tens of km

## 7.3.3 802.11 Frame Format

```
| Frame Control | Duration | Addr 1 | Addr 2 | Addr 3 | Seq Control | Addr 4 | Payload | CRC |
|     2 bytes   |  2 bytes | 6 bytes| 6 bytes| 6 bytes|   2 bytes   | 6 bytes| 0–2312B | 4B  |
```

**Frame Control subfields (bits):** Protocol version (2), Type (2), Subtype (4), To AP (1), From AP (1), More frag (1), Retry (1), Power mgt (1), More data (1), WEP (1), Rsvd (1)

### Address Fields (infrastructure mode)
| Field | Sender (Station → AP) | Receiver (AP → Station) |
|---|---|---|
| Address 1 | AP's MAC | Station's (H1's) MAC |
| Address 2 | Station's (H1's) MAC | AP's MAC |
| Address 3 | Router interface MAC (R1) | Router interface MAC (R1) |
| Address 4 | Used only in ad hoc (AP-to-AP) mode | |

**Why 3 addresses?** AP is a link-layer device; doesn't speak IP. Address 3 lets the AP construct the proper Ethernet frame when forwarding to/from the wired network router.

**Walkthrough (R1 → H1):**
1. Router R1 ARP for H1's MAC, encapsulates in Ethernet frame (src=R1 MAC, dst=H1 MAC)
2. AP converts Ethernet → 802.11: Addr1=H1 MAC, Addr2=AP MAC, Addr3=R1 MAC
3. H1 reads Addr3 to learn the router MAC

**Walkthrough (H1 → R1):**
1. H1 creates 802.11: Addr1=AP MAC, Addr2=H1 MAC, Addr3=R1 MAC
2. AP converts to Ethernet: src=H1 MAC, dst=R1 MAC

### Other Fields
- **Sequence number** — distinguishes new frames from retransmissions (same function as in rdt protocols)
- **Duration** — time reserved for DATA + ACK transmission (used in RTS/CTS too)
- **WEP bit** — indicates encryption in use
- **Payload** — up to 2,312 bytes; typically ≤ 1,500 bytes (IP datagram or ARP)
- **CRC** — 32-bit; critical due to high wireless BER

## 7.3.4 Mobility in the Same IP Subnet

- Multiple BSSs can share same IP subnet (connected via switch, not router)
- When H1 moves from BSS1 to BSS2:
  - H1 detects weakening signal from AP1, receives beacon from AP2
  - H1 disassociates from AP1, associates with AP2
  - H1 keeps same IP address → existing TCP connections maintained
- **Switch forwarding table update problem:**
  - Switch still has old entry pointing H1's MAC → AP1's port
  - Solution: AP2 sends a **broadcast Ethernet frame with H1's source MAC** to the switch → switch updates its table
- If interconnection device were a router (not switch): H1 would need new IP → TCP connections break
- VLANs can extend this same-subnet mobility across large geographic areas

## 7.3.5 Advanced Features

### Rate Adaptation
- Different modulation techniques suit different SNR conditions
- If 2 consecutive frames get no ACK → drop to next lower rate
- If 10 consecutive frames ACKed (or timer expires since last fallback) → step up to next higher rate
- Philosophy similar to TCP congestion control: probe upward until failure, back off on failure

### Power Management
- Mobile device sets **power-management bit** in frame header → AP knows to buffer frames
- Device timer wakes it before AP's next beacon (beacons every **100 ms**)
- Beacon contains list of devices with buffered frames
- If no buffered frames → device goes back to sleep
- Device sends **polling message** to AP to retrieve buffered frames
- Wake-up time: ~250 microseconds
- No frames to send/receive → device can sleep **99% of the time**

## 7.3.6 Personal Area Networks: Bluetooth

- **Wireless Personal Area Networks (WPANs)** / **piconets**
- Range: tens of meters or less; low power; low cost
- Operates in **unlicensed 2.4 GHz ISM band** (same as microwaves, garage openers)
- Data rates: up to **3 Mbps**

### Channel Access
- **TDM** time slots of **625 microseconds**
- During each slot, sender transmits on one of **79 channels**
- Channel changes pseudo-randomly slot-to-slot: **Frequency-Hopping Spread Spectrum (FHSS)**
  - Limits interference from other ISM-band devices to a subset of slots

### Piconet Structure
- **Ad hoc**, self-organizing; up to **8 active devices**
- One device = **master**; rest = **clients/slaves**
  - Master clock defines TDM slot boundaries
  - Master determines frequency-hopping sequence
  - Master controls client entry, TX power (100 mW / 2.5 mW / 1 mW), and uses **polling** to grant TX permission
- Up to **255 parked devices** (sleep mode, wake on master's schedule to receive beacon)
- Parked devices cannot communicate until master changes status to active

### Bootstrap Process
1. **Neighbor discovery:** master broadcasts 32 inquiry messages on different frequencies, repeats up to 128 times; clients listen, back off 0–0.3s (random), reply with device ID
2. **Paging:** master sends 32 paging invitation messages addressed to each desired client on different frequencies; client ACKs; master sends hopping pattern, clock sync, active member address; master polls client to confirm connection
