# 1.5 Protocol Layers and Their Service Models

## 1.5.1 Layered Architecture

### Why Layers?
- Large, complex systems benefit from **modular structure**
- Each layer provides a **service** to the layer above using services from the layer below
- Change the implementation of a layer without affecting other layers — as long as same service interface is preserved
- Drawbacks: duplication of functionality across layers; layer may need info from non-adjacent layer (violates separation)

### The Internet Protocol Stack (5 Layers)

```
┌─────────────────┐
│   Application   │  HTTP, SMTP, FTP, DNS        → message
├─────────────────┤
│    Transport    │  TCP, UDP                     → segment
├─────────────────┤
│    Network      │  IP + routing protocols       → datagram
├─────────────────┤
│      Link       │  Ethernet, WiFi, DOCSIS       → frame
├─────────────────┤
│    Physical     │  bits on wire/fiber/radio     → bit
└─────────────────┘
```

### Layer Descriptions

#### Application Layer
- Network applications + their protocols reside here
- Protocols: **HTTP** (Web), **SMTP** (email), **FTP** (file transfer), **DNS** (name→address)
- Distributed over multiple end systems — protocol exchanges packets between app instances on different end systems
- PDU name: **message**
- Implemented in **software** on end systems

#### Transport Layer
- Transports application-layer messages between **application endpoints**
- Two protocols:
  - **TCP:** connection-oriented; guaranteed delivery; flow control; congestion control; breaks long messages into segments
  - **UDP:** connectionless; no reliability, no flow control, no congestion control
- PDU name: **segment**
- Implemented in **software** on end systems

#### Network Layer
- Moves **datagrams** from source host to destination host
- Transport layer passes segment + destination address → network layer provides delivery to destination transport layer
- Contains:
  - **IP protocol** — defines datagram fields; how routers/end systems act on those fields; **one IP protocol, all Internet components must run it**
  - **Routing protocols** — determine routes datagrams take; Internet has many routing protocols; network admin can choose within a network
- Often called the **IP layer** (IP is the glue binding the Internet)
- PDU name: **datagram**
- Mixed hardware + software implementation

#### Link Layer
- Moves packet from one node to the **adjacent** node along the route
- Network layer passes datagram to link layer → link layer delivers to next node → next node passes up to network layer
- Service depends on specific link-layer protocol
- Some link-layer protocols provide **reliable delivery** (one link, not end-to-end — different from TCP)
- Examples: **Ethernet**, **WiFi**, **DOCSIS** (cable)
- A datagram may use different link-layer protocols on different links along its path
- PDU name: **frame**
- Implemented in **network interface card (NIC)** for a given link

#### Physical Layer
- Moves **individual bits** within a frame from one node to the next
- Protocols are link-dependent AND medium-dependent (twisted pair, fiber, coaxial)
- Ethernet has separate physical-layer protocols for twisted-pair, coaxial, fiber
- PDU name: **bit**

### What Each Network Device Implements

| Device | Layers Implemented |
|--------|-------------------|
| Host (end system) | All 5 layers |
| Router | Layers 1–3 (Physical, Link, Network/IP) |
| Link-layer switch | Layers 1–2 (Physical, Link) |

- Hosts implement all layers — consistent with "intelligence at the edges" design principle
- Link-layer switches: recognize layer-2 (Ethernet) addresses but not IP addresses
- Routers: implement IP but not application or transport layers

## 1.5.2 Encapsulation

Data flows **down** the stack at sender, **up and down** through intermediate devices, and **up** the stack at receiver.

### Encapsulation Process (Sender)

```
Application:  [  M  ]                           → message M
Transport:    [ Ht | M ]                         → segment (Ht = transport header)
Network:      [ Hn | Ht | M ]                    → datagram (Hn = network header)
Link:         [ Hl | Hn | Ht | M | Tl ]          → frame (Hl = link header, Tl = trailer)
Physical:     bits transmitted on medium
```

- Each layer adds **header information** (possibly trailer) around the payload from the layer above
- Payload = packet from layer above
- Headers contain control info for the corresponding receiver-side layer (e.g., source/dest addresses, error detection bits)

### Encapsulation Key Points
- **Transport-layer segment** encapsulates application-layer message
- **Network-layer datagram** encapsulates transport-layer segment
- **Link-layer frame** encapsulates network-layer datagram
- At each intermediate node, de-encapsulation occurs up to that node's highest implemented layer, then re-encapsulation occurs going down for forwarding
- Large messages may be split into multiple segments, each becoming a separate datagram

### Postal Analogy
- Application message → memo
- Transport segment → interoffice envelope (with recipient name/dept)
- Network datagram → postal envelope (with full postal address)
- Link frame → handled by each postal facility along the route

### OSI Reference Model (7 Layers)

The Internet stack (5 layers) omits two layers present in the ISO OSI model:
- **Presentation layer:** allows applications to interpret meaning of exchanged data (encryption, compression, data description)
- **Session layer:** provides delimiting and synchronization of data exchange (checkpointing, recovery)

These functions, if needed, must be implemented in the application itself in the Internet architecture.
