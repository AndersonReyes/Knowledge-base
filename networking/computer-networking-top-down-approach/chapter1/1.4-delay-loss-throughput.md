# 1.4 Delay, Loss, and Throughput in Packet-Switched Networks

## 1.4.1 Overview of Delay

A packet suffers **four types of delay** at each node (router) along its path:

```
d_nodal = d_proc + d_queue + d_trans + d_prop
```

### Processing Delay (`d_proc`)
- Time to examine packet header + determine output link
- Check for bit-level errors
- Typically **microseconds or less** in high-speed routers
- Strongly influences a router's **maximum throughput**

### Queuing Delay (`d_queue`)
- Time waiting in output buffer for link to become free
- Depends on number of packets already queued and congestion level
- **Variable** — ranges from zero (empty queue) to large (heavy traffic)
- Typically **microseconds to milliseconds**
- Only delay component that varies packet-to-packet

### Transmission Delay (`d_trans`)
- Time to push all packet bits onto the link
- Formula: `d_trans = L / R`
  - L = packet length in bits
  - R = link transmission rate in bits/sec
- Function of **packet length + link rate** — NOT distance
- Typically **microseconds to milliseconds**
- Negligible at 10 Mbps+; significant at low speeds (dial-up)

### Propagation Delay (`d_prop`)
- Time for a bit to propagate from start of link to next router
- Formula: `d_prop = d / s`
  - d = distance between routers
  - s = propagation speed ≈ 2×10⁸ to 3×10⁸ m/s (depends on medium)
- Function of **distance** — NOT packet length or link rate
- Negligible within a campus; **hundreds of milliseconds** for geostationary satellite links

### Transmission vs. Propagation Delay — Key Distinction

| Delay | Depends on | Analogy |
|-------|-----------|---------|
| Transmission | Packet length, link rate | Time for toll booth to process all cars in caravan |
| Propagation | Distance between routers | Time for a car to drive between toll booths |

**Tollbooth analogy:**
- 10 cars in caravan; tollbooth serves 1 car/12s; road speed 100 km/h; distance 100 km
- Transmission delay: (10 cars) / (5 cars/min) = **2 min**
- Propagation delay: 100 km / (100 km/h) = **60 min**
- Total: **62 min**

## 1.4.2 Queuing Delay and Packet Loss

### Traffic Intensity

```
Traffic intensity = La / R
```
- L = packet size (bits)
- a = average packet arrival rate (packets/sec)
- R = link rate (bits/sec)
- La = average arrival rate of bits (bits/sec)

**Rules:**
- `La/R > 1`: queue grows without bound → delay approaches **infinity** (avoid this!)
- `La/R ≤ 1`: delay depends on traffic pattern
  - Periodic arrivals: potentially zero queuing delay
  - Bursty arrivals: can cause significant average queuing delay

**Golden rule:** Design your system so that traffic intensity ≤ 1.

### Queuing Delay for Burst Arrivals
- N packets arrive simultaneously, then gap, periodically
- nth packet queuing delay = **(n–1) × L/R**
- Average queuing delay = sum of individual delays / N

### Traffic Intensity vs. Average Queuing Delay
- Near 0: arrivals sparse, nearly empty queue → near-zero delay
- Approaching 1: queue grows large; small increase in intensity → large delay increase
- **Non-linear relationship** — exponential-like growth as intensity → 1

### Packet Loss
- Output buffers have **finite capacity**
- When buffer full: arriving packet (or queued packet) is **dropped**
- From end-system perspective: packet sent into network but never arrives at destination
- Lost packets may be **retransmitted** end-to-end (e.g., by TCP)
- Fraction of lost packets increases with traffic intensity

## 1.4.3 End-to-End Delay

For uncongested network (negligible queuing), N-1 routers between source and destination:

```
d_end-end = N × (d_proc + d_trans + d_prop)
```
where `d_trans = L/R` and each router/source has same processing delay and same link rate.

### Traceroute
- Sends N special packets toward destination (one per hop)
- Each router n returns message to source when it receives packet n
- Source records round-trip delay for each router → reconstructs path + delays
- Repeats experiment 3 times → reports 3 RTT values per hop
- `*` = packet lost, fewer than 3 RTTs shown
- RTT to hop n+1 can be **less than** RTT to hop n (queuing delay varies)

**Example traceroute output (gaia.cs.umass.edu → UPMC Paris):**
- 14 routers, big jump between routers 7→8 due to transatlantic fiber-optic link (~77ms RTT)

### Other End-System Delays
- **Media packetization delay** (VoIP): time to fill a packet with encoded speech before transmitting
- **Shared-medium access delay** (WiFi/cable): deliberate delay waiting to access shared medium

## 1.4.4 Throughput in Computer Networks

### Definitions
- **Instantaneous throughput:** rate (bits/sec) at which destination receives data at a given instant
- **Average throughput:** F bits transferred in T seconds → `F/T bits/sec`

### Bottleneck Link

For server→client path with N links of rates R1, R2, ..., RN:
```
throughput = min{R1, R2, ..., RN}
```
**The bottleneck link** (minimum rate link) determines end-to-end throughput.

**Two-link example:**
- Rs = server-to-router link rate
- Rc = router-to-client link rate
- `throughput = min{Rs, Rc}`
- Transfer time for F-bit file: `F / min{Rs, Rc}`

**Practical observation:** Core of Internet is **over-provisioned** with high-speed links → in practice, bottleneck is typically the **access network** (Rs or Rc).

### Shared Core Link (Multiple Flows)

10 simultaneous downloads; shared core link rate R:
- Each download gets `R/10` from shared link
- If `R/10 < min{Rs, Rc}` → shared link is the bottleneck
- Example: Rs = 2 Mbps, Rc = 1 Mbps, R = 5 Mbps → each gets 500 kbps (bottleneck = shared R/10)

**Key insight:** Throughput depends not only on transmission rates of links along path, but also on **intervening traffic** sharing those links.
