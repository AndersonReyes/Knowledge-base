# 5.3 Intra-AS Routing: OSPF

**Source:** Kurose & Ross, *Computer Networking: A Top-Down Approach*, 8th ed., pp. 395–399

---

## Why Autonomous Systems (ASes)?

Two problems with a single flat routing domain across the whole Internet:

| Problem | Detail |
|---|---|
| **Scale** | Hundreds of millions of routers — storing/computing/broadcasting routing info for all is prohibitive; DV would never converge |
| **Administrative autonomy** | ISPs want to run their own routing algorithm internally, hide network topology, set their own policies |

**Solution:** Organize routers into **Autonomous Systems (ASes)**

- AS = group of routers under same administrative control
- Each AS has a globally unique **Autonomous System Number (ASN)** [RFC 1930]
- ASNs assigned by ICANN regional registries
- Routing algorithm within an AS = **intra-AS routing protocol**

---

## OSPF Overview

- **Open Shortest Path First** — version 2 defined in [RFC 2328]
- "Open" = publicly available specification (vs. Cisco's proprietary EIGRP)
- Closely related: IS-IS (also widely deployed for intra-AS routing)
- **Type:** Link-state protocol using Dijkstra's algorithm
- **Transport:** Carried directly in IP datagrams (upper-layer protocol = **89**)
  - OSPF must implement its own reliable message transfer and link-state broadcast
  - HELLO messages used to check link liveness and neighbor discovery

### How It Works
1. Each router constructs a complete topological map (graph) of the entire AS
2. Each router runs Dijkstra's shortest-path algorithm independently
3. Each router builds a shortest-path tree rooted at itself
4. Individual link costs configured by the network administrator

### Link Cost Configuration Options
- All costs = 1 → minimum-hop routing
- Costs inversely proportional to capacity → favor high-bandwidth links
- Operator can reverse-engineer link weights to achieve desired traffic engineering goals [Fortz 2000, 2002]
- OSPF does not mandate link weight policy — that is the admin's job

### Broadcast Behavior
- Router broadcasts link-state info to **all** routers in AS (not just neighbors)
- Broadcast triggered by: link state change (cost/up/down)
- Periodic re-broadcast: at least every **30 minutes** (adds robustness per RFC 2328)

## OSPF Advanced Features

### Security
- By default: OSPF packets unauthenticated (can be forged)
- **Simple authentication:** shared password in plaintext — not secure
- **MD5 authentication:** shared secret key; OSPF packet + secret → MD5 hash appended; sequence numbers prevent replay attacks

### Multiple Equal-Cost Paths
- OSPF allows multiple paths of equal cost to be used simultaneously (traffic splitting)
- Single path need not be chosen when multiple equal-cost paths exist

### Multicast Support
- **MOSPF** [RFC 1584] — extensions to OSPF for multicast routing
- Uses existing OSPF link database + new link-state advertisement type

### Hierarchical Structure (Areas)

```
                    ┌─────────────────────┐
                    │     Backbone Area   │  ← Area 0
                    │  (all border routers│
                    │   must be here)     │
                    └──────┬──────┬───────┘
                           │      │
               ┌───────────┘      └──────────┐
         ┌─────┴──────┐              ┌───────┴─────┐
         │   Area 1   │              │   Area 2    │
         │            │              │             │
         └────────────┘              └─────────────┘
```

- Each area runs its own OSPF link-state algorithm internally
- Routers within an area only flood link state within that area
- **Area border routers:** responsible for routing packets outside the area; must reside in the backbone
- **Backbone area (Area 0):** routes traffic between all other areas; contains all area border routers
- **Inter-area routing path:** intra-area → backbone → intra-area

---

## OSPF vs. Scale and Admin

| Concern | OSPF Approach |
|---|---|
| Too many routers | Split AS into areas; each area runs its own LS independently |
| Hiding topology | Area border routers summarize routes; internal topology stays internal |
| Multiple equal-cost paths | Supported natively |
| Security | MD5 authentication of OSPF messages |
