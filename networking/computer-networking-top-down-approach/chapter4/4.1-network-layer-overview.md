# 4.1 Overview of Network Layer

## Core Functions

- **Forwarding** (data plane): router-local action — moves packet from input link to correct output link
  - Timescale: nanoseconds
  - Implementation: hardware
- **Routing** (control plane): network-wide — determines end-to-end paths
  - Timescale: seconds
  - Implementation: software

> Forwarding = one interchange. Routing = planning the whole trip.

## Forwarding Table

- Each router has a forwarding table
- Incoming packet header fields index the table → yields output link interface
- Table is populated by either:
  - **Traditional**: routing algorithm running in each router communicates via routing protocols (OSPF, BGP)
  - **SDN**: remote controller computes forwarding tables and pushes them to routers

## Control Plane Approaches

### Traditional (Per-Router)
- Routing algorithm runs in each router
- Routers exchange routing messages (routing protocol)
- Data plane and control plane co-located in router hardware

### SDN (Centralized Remote Controller)
- Data plane: same as traditional (routers forward packets)
- Control plane: physically separate remote controller computes forwarding tables
- Controller communicates with routers to install forwarding table entries
- Controller often implemented in software → "software-defined"
- Controller may be open-source, allowing ISP innovation

## Network Service Model

Defines characteristics of end-to-end packet delivery. Possible services:

| Service | Description |
|---|---|
| Guaranteed delivery | Packet eventually arrives |
| Bounded delay delivery | Arrives within specified delay (e.g., ≤100 ms) |
| In-order delivery | Packets arrive in send order |
| Guaranteed minimum bandwidth | Emulates a link of specified bit rate |
| Security | Encryption/decryption at source/destination |

### Internet's Actual Service Model: Best-Effort
- No guaranteed delivery
- No ordering guarantee
- No delay guarantee
- No bandwidth guarantee
- "Best-effort" = effectively no guarantees, but in practice sufficient for most apps

**Historical alternatives**: ATM provided guaranteed in-order delay, bounded delay, guaranteed min bandwidth. Intserv (RFC 1633) aimed for end-to-end delay guarantees. Neither displaced best-effort IP.
